# meeting-facilitation

1. 读取当前议题、必要产出、验收条件、硬约束与剩余预算，区分已提交事实和待验证主张。
2. 轮次发布后，先依据公开证据对原目标形成有界答案，说明核心结论、置信程度、关键适用边界和限制，再对照参与者职责、未解决问题与阻塞检查剩余缺口；有界答案不等于 completed。
3. 开轮只安排明确可能改变核心结论、置信程度或关键边界的可执行工作；在 plan rationale 写明当前判断、预期改变、具体证据机会、现有证据为何不足，roundGoal 与之对应，并说明承担者、复核和停止条件。负面审核或可修缺陷不自动要求继续；不影响判断的引用、措辞、展示问题保留为限制，不单独开轮。
4. 比较连续公开轮次的核心判断与实际增量。判断持续不变时，继续开轮必须有新的关键证据机会；换表述、重复限制或新发现的次要缺陷不成立。不追求无缺陷证据包或全正面审核，不以固定轮数代替判断。当前议题无实质增量路径时收口并扫描后续已授权议题；新议题只记录为候选，不自动替换目标。
5. 单项取证或复核受阻时，轮次收口后在 Manager plan 的 blockingReason 记录事实与原因，在 rationale 说明受影响结论、解除条件和可继续工作；不把局部阻塞扩大为整场会议停止。前轮 Contribution 关闭不限制 Contributor 在新轮重新举手。
6. 依据已公开结果说明满足了什么、还缺什么。不以发言数量、自然语言赞同或计划代替验收事实。
7. 逐项核对目标缺口、取证承担者的真实能力与资源、预算和新增信息价值；Manager 自己没有取证工具不表示 Contributor 不能执行。仅对达到第 3、4 项实质增量门槛的缺口，检查作者能否用已取得材料修正公开 Review 指出的引用、检索记录或主张限定问题，再判断相关路径是否耗尽，继续不依赖阻塞的取证；不凭空假定可用来源、凭据或未执行的检索范围。无 open Round 时自动激活首个可推进的已授权 pending Agenda，保留旧议题阻塞并显式 deferred/closed/completed；激活后重读再规划开轮，无需 Captain 确认。新增 candidate 仍等待 Captain 处置，不越权，也不因等待用户处置直接结束。
8. 提交 `stop_agenda` 后，在独立的后续通知阶段重新读取会议，扫描待处理议题、候选议题、未收口贡献和可执行的取证路径；有达到实质增量门槛的路径则继续推进，待合法用户处置则记录等待原因；所有影响原目标判断的相关路径均已完成、无实质新增价值或有明确不可解除的阻塞且无其他后续工作时，才由 Manager 明确正常结束结果并保留未解决限制。
