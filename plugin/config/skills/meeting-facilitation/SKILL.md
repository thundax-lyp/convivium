# meeting-facilitation

1. 读取当前议题、必要产出、验收条件、硬约束与剩余预算，区分已提交事实和待验证主张。
2. 对照参与者职责、现有证据、未解决问题与阻塞，指出本轮需要回答的具体问题及证据缺口。
3. 形成有限计划：预期产出、依据、承担者、必要复核和停止条件。避免重复已有证据；独立交叉验证须说明理由。
4. 讨论偏离、重复或长期无进展时，围绕原目标收敛；新议题只记录为候选，不自动替换目标。
5. 单项取证或复核受阻时，轮次收口后在 Manager plan 的 blockingReason 记录事实与原因，在 rationale 说明受影响结论、解除条件和可继续工作；不把局部阻塞扩大为整场会议停止。前轮 Contribution 关闭不限制 Contributor 在新轮重新举手。
6. 依据已公开结果说明满足了什么、还缺什么。不以发言数量、自然语言赞同或计划代替验收事实。
7. 逐项核对目标缺口、取证承担者的真实能力与资源、预算和新增信息价值；Manager 自己没有取证工具不表示 Contributor 不能执行。先检查作者能否用已取得材料修正公开 Review 指出的引用、检索记录或主张限定缺口，再判断路径是否耗尽，继续不依赖阻塞的取证；不凭空假定可用来源、凭据或未执行的检索范围。无 open Round 时自动激活首个可推进的已授权 pending Agenda，保留旧议题阻塞并显式 deferred/closed/completed；激活后重读再规划开轮，无需 Captain 确认。新增 candidate 仍等待 Captain 处置，不越权，也不因等待用户处置直接结束。
8. 提交 `stop_agenda` 后，在独立的后续通知阶段重新读取会议，扫描待处理议题、候选议题、未完成任务和可执行的取证路径；有路径则继续推进，待合法用户处置则记录等待原因；所有相关路径均已完成、无新增价值或有明确不可解除的阻塞且无其他后续工作时，才由 Manager 明确正常结束结果并保留未解决限制。
