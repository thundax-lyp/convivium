# meeting-facilitation

1. 读取当前议题、必要产出、验收条件、硬约束与剩余预算，区分已提交事实和待验证主张。
2. 研究问题的拆分、探索、验证与收拢使用 `research-planning`。首次拆分及重新规划前显式加载；在 plan rationale 和 roundGoal 中表达当前问题、证据缺口、预期产出和选择依据，不以固定轮数代替判断。
3. 规划开轮前核对承担者、实际能力、资源、权限、期限和预算。先提交 Manager plan，成功后用新版本及 planId 开轮；参与者举手由 Manager 处置，接纳后才取得 Contribution。
4. 轮次发布后重读当前公开事实，再评估后续工作。仅在有实质新增信息价值的可执行路径时继续；有界答案不等于正式目标已满足。
5. 单项取证或复核受阻时，轮次收口后在 Manager plan 的 blockingReason 记录事实与原因，在 rationale 说明受影响结论、解除条件和可继续工作；不把局部阻塞扩大为整场会议停止。前轮 Contribution 关闭不限制 Contributor 在新轮重新举手。
6. 依据已公开结果说明满足了什么、还缺什么。不以发言数量、自然语言赞同或计划代替验收事实。
7. 逐项核对目标缺口、取证承担者的真实能力与资源、预算和新增信息价值；Manager 自己没有取证工具不表示 Contributor 不能执行。仅对达到研究规划的实质增量门槛的缺口，检查作者能否用已取得材料修正公开 Review 指出的引用、检索记录或主张限定问题，再判断相关路径是否耗尽，继续不依赖阻塞的取证；不凭空假定可用来源、凭据或未执行的检索范围。无 open Round 时自动激活首个可推进的已授权 pending Agenda，保留旧议题阻塞并显式 deferred/closed/completed；激活后重读再规划开轮，无需 Captain 确认。新增 candidate 仍等待 Captain 处置，不越权，也不因等待用户处置直接结束。
8. 提交 `stop_agenda` 后，收到独立投递的 `agenda_stopped` 即重新读取会议，扫描待处理议题、候选议题、未收口贡献和可执行的取证路径。该计划只记录停止判断，Agenda 和 stop plan 仍为 `active` 是正常结果；不等待 `stopped`、`processed` 或第二条通知。在本次 turn 作出下一步决定：有达到实质增量门槛的路径则继续推进，待合法用户处置则记录等待原因；所有影响原目标判断的相关路径均已完成、无实质新增价值或有明确不可解除的阻塞且无其他后续工作、无 open Round 时，使用最新读取版本调用 `convivium_end_meeting`，明确正常结束结果并保留未解决限制。

## 工具与权限

仅使用当前 Host 授予的工具。Skill 描述工作方法，不授予会议身份、写权限或额外网络权限；读取本文件不执行脚本。
