# Meeting 与 Timeline UI 框架图（讨论稿）

> 状态：讨论设计稿，不作为实现依据。本文记录已讨论的 Panel 职责和候选信息架构；涉及新字段、projection、事件粒度和跨 Panel 导航的内容仍需形成正式需求、接口与设计后才能实现。

## 设计目标

Convivium 在 DSH Web 中提供两个互补但独立的只读视图：

- **Meeting Panel** 回答“会议最终得出了什么”，默认呈现一份可以直接阅读、转发和执行的结论稿。
- **Timeline Panel** 回答“会议是怎样推进到结果的”，按时间和会议身份呈现过程事件。

两者读取同一组已提交 Meeting 事实的不同 projection，不互相复制权威状态，也不从 UI 展示推导新的领域事实。DSH 自带的“轨迹”继续表示 Agent 执行轨迹；Convivium 的“时间线”只表示会议领域过程。

## 整体框架

```text
DSH 会话页面
│
├─ 对话                  DSH 提供：用户与 Agent 的消息交互
├─ 轨迹                  DSH 提供：Agent、Tool 与运行步骤
├─ 会议                  Convivium 提供：会议结果视图
└─ 时间线                Convivium 提供：会议过程视图
                           面板标题：会议时间线

                         ┌──────────────────────────────┐
                         │ 已提交的 Meeting 事实         │
                         └──────────────┬───────────────┘
                                        │
                         ┌──────────────┴───────────────┐
                         │                              │
                 ┌───────▼────────┐             ┌───────▼────────┐
                 │ Result         │             │ Timeline       │
                 │ projection     │             │ projection     │
                 └───────┬────────┘             └───────┬────────┘
                         │                              │
                 ┌───────▼────────┐             ┌───────▼────────┐
                 │ Meeting Panel  │◄───────────►│ Timeline Panel │
                 │ 结论与证据索引 │   定位链接   │ 过程与事件     │
                 └────────────────┘             └────────────────┘
```

候选定位链接只改变展示位置，不改变 Meeting 状态。例如，从 Meeting 的一条结论定位到形成该结论的 Timeline 事件，或从 Timeline 的决策事件返回 Meeting 中的正式结果。

## Meeting Panel：结果视图

### 页面框架

```text
┌──────────────────────────────────────────────────────────────────┐
│ 会议议题                                             [已归档]     │
│ 参与者 · 开始/结束时间 · 耗时 · 轮次                          刷新 │
├──────────────────────────────────────────────────────────────────┤
│ 核心判断                                                         │
│ 2～4 行能够独立成立的会议结论。                                  │
├──────────────────────────────────────────────────────────────────┤
│ 关键结论                                                         │
│ 1. 结论摘要                                      [查看 3 条证据] │
│ 2. 结论摘要                                      [查看 2 条证据] │
│ 3. 结论摘要                                      [存在分歧]      │
├───────────────────────┬───────────────────────┬──────────────────┤
│ 决策                  │ 行动项                │ 未决问题         │
│ 已接受的正式决定      │ owner / 状态 / 条件   │ 风险与后续问题   │
├───────────────────────┴───────────────────────┴──────────────────┤
│ 分析正文                                                         │
│                                                                  │
│ ## 判断依据                                                      │
│ 连续的报告式内容；引用与证据入口紧跟对应主张。                   │
│                                                                  │
│ ## 反证、分歧与限制                                              │
│ 明确结论成立的条件、不确定性、反面意见和未覆盖边界。             │
│                                                                  │
│ ## 适用与不适用                                                  │
│ 说明结果能支持什么，以及不能据此推断什么。                       │
├──────────────────────────────────────────────────────────────────┤
│ 证据与贡献                                             [展开]     │
│ 按结论、轮次或贡献者查看正式发言、Evidence 与 Review。           │
├──────────────────────────────────────────────────────────────────┤
│ 一句话总结                                                       │
│ 可以脱离上下文阅读的最终结论。                                   │
├──────────────────────────────────────────────────────────────────┤
│ 技术信息                                               [展开]     │
│ Meeting ID · version · archive version · 原始 round ID            │
└──────────────────────────────────────────────────────────────────┘
```

### 阅读优先级

Meeting Panel 默认采用以下顺序：

1. 核心判断；
2. 关键结论；
3. 决策、行动项和未决问题；
4. 支撑结论的分析正文；
5. 反证、分歧、限制及适用边界；
6. 可追溯的证据和原始贡献；
7. 归档与内部标识符。

结论稿以连续阅读为主，不把每个字段都切成独立卡片。卡片只用于状态、摘要和可执行事项；完整论证保留标题、段落、表格和就近引用形成的文档结构。

### 原始材料的降级展示

正式发言不再默认作为连续长列表铺开。候选展示方式为：

```text
证据与贡献
├─ 按关键结论
│  └─ 结论 → 支持证据 / 反证 / Review / 贡献者
├─ 按轮次
│  └─ 第 1 轮 → 第 2 轮 → ……
└─ 按贡献者
   └─ 身份 → 正式发言摘要 → 结构化正文
```

每条正式发言首先显示贡献者、轮次、主题和摘要；“观察、解释、方法、主张、反证、不确定性、限制”等结构化字段按需展开。内部 ID 保留在技术详情或复制入口中，不作为主要标题。

## Timeline Panel：过程视图

### 页面框架

```text
┌──────────────────────────────────────────────────────────────────┐
│ 会议时间线                                      [全部事件 ▾]     │
│ 会议议题 · 当前状态                    搜索  筛选  缩放  回到现在 │
├────────────┬────────────┬────────────┬────────────┬──────────────┤
│ 时间       │ Captain    │ Manager    │ Contributor│ Reviewer     │
├────────────┼────────────┼────────────┼────────────┼──────────────┤
│ 10:00      │ 创建会议   │            │            │              │
│            │ ●          │            │            │              │
│ 10:03      │            │ 开启第 1 轮│            │              │
│            │            │ ●──────────┼──────────► │              │
│ 10:05      │            │            │ A 举手     │              │
│ 10:06      │            │ 接纳       │            │              │
│ 10:18      │            │            │ A 提交证据 ├────────────► │
│ 10:24      │            │            │            │ 审核完成     │
│ 10:30      │            │ 发布第 1 轮│            │              │
│ 10:35      │ 处置议题   │            │            │              │
│   …        │            │            │            │              │
│ 11:20      │ 结束会议   │            │            │              │
│ 11:22      │            │            │            │              │
│            │              系统：会议已归档                       │
└────────────┴────────────┴────────────┴────────────┴──────────────┘
```

泳道按会议身份或身份组组织，而不是按 DSH Session 或模型组织。系统提交、暂停、恢复、失败、超时、归档等没有自然发言人的事件使用独立“系统”泳道或跨泳道节点。

### 事件卡片

```text
┌────────────────────────────────────────────┐
│ 10:30 · Manager                            │
│ 发布第 1 轮                                │
│ 2 条正式贡献 · 2 份 Evidence · Review 完成 │
│ [查看事件详情] [在会议结果中定位]          │
└────────────────────────────────────────────┘
```

事件详情只显示 caller 可见的已提交事实。DSH 隐藏推理、私有取证材料、凭据、capability、未公开 Session 历史和内部工具过程不进入 Timeline。

### 候选筛选

- 身份：Captain、Manager、Contributor、Reviewer、系统；
- 事件类别：议题、轮次、举手与贡献、Evidence、Review、决策、风险、控制、归档；
- 状态：成功、拒绝、等待、撤销、失败；
- 关联对象：Agenda、Round、Contribution、Evidence、Decision。

筛选只改变当前 projection 的展示，不改变会议状态或可见性授权。

## 两个 Panel 的协作

```text
Meeting：关键结论
    │
    ├─“查看证据形成过程”──────────────► Timeline：相关事件集合
    │
    └─“查看正式贡献”─────────────────► Meeting：证据与贡献详情

Timeline：发布、决策或归档事件
    │
    ├─“查看事件详情”─────────────────► Timeline：事件详情
    │
    └─“在会议结果中定位”─────────────► Meeting：对应结果段落
```

两个 Panel 不承担 DSH“对话”和“轨迹”的职责：

| 视图 | 回答的问题 | 主要对象 |
| --- | --- | --- |
| 对话 | 用户和 Agent 说了什么？ | DSH message |
| 轨迹 | Agent 和 Tool 怎样执行？ | DSH execution trace |
| 会议 | 会议最终形成了什么？ | 结论、决策、事实、问题、证据索引 |
| 时间线 | 会议事实怎样随时间形成？ | 已提交 Meeting event/projection |

## 当前结论与未决项

### 已形成的讨论结论

- Meeting 与 Timeline 使用两个独立 Panel。
- Meeting 是结果视图，Timeline 是过程视图。
- Timeline 面向会议领域事件，不替代 DSH 的 Agent“轨迹”。
- Meeting 默认展示综合结论，原始发言、内部 ID 和归档诊断降为可展开详情。
- 两个 Panel 可以通过只读定位链接互相追溯，但不能因此改变领域状态。

### 进入正式需求前需要确认

1. 当前 Meeting 事实是否足以生成稳定的综合结论稿；若不足，综合产物由哪个角色产生、何时提交、如何版本化。
2. Timeline 的事实源是现有领域记录的纯 projection，还是需要新增公开事件；不得从日志或隐藏运行过程反推领域事实。
3. Timeline 的最小事件集合、排序键、同一时间事件的稳定顺序和跨恢复显示语义。
4. 参与者、开始/结束时间、耗时、行动项、适用边界等字段哪些属于现有事实，哪些是候选新增需求。
5. 跨 Panel 定位使用何种稳定对象 ID，以及目标内容不可见、已撤销或不存在时的表现。
6. 多会议选择器、窄屏布局、泳道过多时的折叠与横向滚动规则。
7. “时间线”作为 `conversation.view` 标签是否足够区别于“轨迹”；当前候选为标签“时间线”、面板标题“会议时间线”。
