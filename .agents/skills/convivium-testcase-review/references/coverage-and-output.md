# 审查分级、清单与输出

范围确定后读取本文，建立文件清单与集合比较记录；收敛 findings 和输出结果时按本文核对。审查方法与执行边界见 [SKILL.md](../SKILL.md)。

## Finding 分级与收敛

参考 [PR Review 的分级口径](../../convivium-pr-review/references/review-checks.md#findings-门槛)，按当前可触发影响分级；下表将其应用到测试资产，审查范围仍遵循本 Skill 的范围约定。优先级表示处置紧迫性，不代表证据置信度。缺少依据的推断进入待核实事项，不降为 P3 来充当已确认问题。

| 等级 | 判断标准与处置 |
| --- | --- |
| P0 | 执行当前测试或清理路径会造成严重安全事件、不可恢复的数据损坏或大范围不可用，有明确执行链路和当前影响证据；立即停止相关执行并修复。不能由被测功能的重要性或假想漏测后果推定 |
| P1 | 核心验收或必需门禁失效，直接掩盖已确认的核心错误或高风险回归，或常见执行路径持续阻断关键验证；应在依赖该证据交付前修复 |
| P2 | 当前合理场景下，测试错误放行违反契约的输入或结果、错误拒绝合法行为，或隔离、异步等待、清理问题使相关验证不可靠；应安排修复。须指出具体错误、输入和断言如何失效 |
| P3 | 不影响已确认核心保护的局部验证可信度、重复代码、冗余自测、无关 fixture 依赖或维护问题，有明确成本和更小替代方式；可低优先级修复。纯风格偏好不报告 |

同类资产问题可能有不同等级：fixture 自测通常属于 P3；若替身直接提供验收结果、让必需的真实边界验证错误通过，应按实际证据损失定为 P2 或 P1。耗时问题需要运行数据，不按 case 数量定级。

输出前按共同根因、触发条件和修复位置合并 findings。同一生产缺陷与直接掩盖它的测试缺口合并报告，说明生产影响与测试证据各自的边界；只有独立触发、独立影响和独立修复边界才拆分。分别核对 finding 是否成立、等级是否准确、处置是否最小，优先增强已有 case，不将一处缺口扩展为假想边界清单。

## 输出与执行

使用中文，沿用 PR review 的 findings-first 风格：先按 P0 → P3 输出已确认问题，再给审查范围、验证缺口和摘要。每项使用可点击文件链接及最小相关行号；工作区审查不要求位置属于 diff。与 PR/module review 组合时继承其输出格式，将下面的保护承接信息纳入对应 finding。

### Findings format

```md
### [P2] 简短、可执行的标题

- 位置：文件链接、最小相关行号及 case/helper 名称。
- 问题：具体错误及共同根因。
- 触发：前置条件、输入、实际执行路径与断言。
- 当前影响：错误放行、错误失败、保护缺失或具体维护成本；区分生产缺陷与测试证据问题。
- 最小处置：增强 / 合并 / 简化 / 替代 / 删除，以及能够消除触发条件的最小改动。
- 保护承接：原本要识别的具体错误；保留哪些 case、输入和断言继续识别它，或明确失去的证据及允许取舍的依据。
- 范围上限：最容易被顺带扩张的相邻能力；无则写“无”。
- 证据：规则、需求、接口、源码或实际命令结果；标明静态论证和动态验证。
```

`最小处置` 定义修复边界，不设计完整实现；`保护承接` 不能只写“已有覆盖”，也不能以全绿或 coverage 不变证明删除安全。

### Final output

Findings 之后按以下结构收口。逐文件列出目标测试、fixture/helper、必要生产代码和依据文档，路径使用可点击链接；可按职责分组，但不得用目录名或“相关文件”代替文件清单。同一文件只计一次，同时属于目标和上下文时归入目标，不要求逐 case 建立台账。

- `reviewed`：已完成与本次问题相关的内容、调用路径或断言审查。只读相关片段时注明章节、符号或行段，不宣称审过整个文件。
- `deferred`：目标文件或必要上下文尚未完成判断，说明具体缺口。仅搜索命中或打开过不等于 reviewed；纯搜索候选经排除后不计入，已声明目标被排除时解释范围调整。
- 目标测试文件只有单例有效性和相关集合比较都完成才标记 reviewed。仅完成一项时标记 deferred，注明缺少的判断；fixture/helper 按其职责审查消费边界与必要成本。
- 用简短的集合比较表记录实际比较过的候选组：文件/case 或参数行、共同保护、独有证据或承接断言、保留/精简/待核实及理由。只记录有取舍意义的组，不为每个 case 建立台账；已在 finding 说明的组可以引用 finding。未发现重复候选时说明实际比较范围和保留依据，不为凑表虚构候选。
- 分别统计目标文件、必要上下文的 reviewed/deferred 数量；每组 total 必须等于两种状态之和，总计必须等于表中唯一文件数。有 deferred 或目标遗漏时，Coverage 为 incomplete。

```md
## Coverage

- 基线与目标范围：当前工作区或指定版本，以及解析后的路径、模块或符号。

### Reviewed files

| 文件 | 角色 | 状态 | 实际审查内容或缺口 |
| --- | --- | --- | --- |
| 文件链接 | 目标 / 必要上下文 | reviewed / deferred | case、helper、生产符号或文档章节；未完成时说明原因 |

- 目标文件：total N；reviewed N；deferred N。
- 必要上下文：total N；reviewed N；deferred N。
- 总计：唯一文件 N；reviewed N；deferred N。

### 集合比较

| 用例组 | 共同保护 | 独有证据或承接断言 | 处置与理由 |
| --- | --- | --- | --- |
| 文件链接及 case/参数行 | 具体错误或边界 | 保留差异或删除后的承接位置 | 保留 / 精简 / 待核实 |

- 集合比较状态：complete / incomplete；存在待核实项时说明缺失证据。
- Coverage 状态：complete / incomplete；逐文件审查和集合比较均闭合才为 complete。

## Validation gaps

- 实际验证：命令、结果；复用旧证据时注明原基线。
- 未验证与待核实：未运行边界、阻塞原因及影响结论的缺失依据；无则写“无”。
- Validation 状态：verified / partial / not-run / blocked。

## Review summary

- 结论：未发现可行动问题 / 存在需修复问题 / 补齐审查后再决定。
- P0 / P1 / P2 / P3 数量：按收敛后的 findings 统计。
- 最主要风险：当前影响最大的保护缺口或成本；无则写“无”。
- 精简结论：可删除/合并的资产及保护承接，或实际比较后的保留理由。case 减量只在可确定时给出，不设置目标比例，不以参数化代码减量冒充 case 减量。
```

Coverage 仅表示声明的审查范围是否完成，不表示测试覆盖率或产品需求全部已验证；Validation 独立记录实际执行证据，部分通过但仍有阻塞时写 partial 并列出阻塞项。独立测试审查不输出 PR 合并建议。

范围完成且无 finding 时，开头输出 `No actionable findings.`；没有 confirmed finding 但范围未完成时，输出 `No confirmed findings, but review coverage is incomplete.`。不得把未读或待核实当作没有问题。
