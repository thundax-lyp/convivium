# Testcase Review

仅由用户显式调用。按 [Test Rules](../../../docs/00-governance/TEST-RULES.md) 判断测试是否有效、值得保留及可以简化，按根 `AGENTS.md` 读取行为依据，按 [Engineering Rules](../../../docs/00-governance/ENGINEERING-RULES.md#validation-and-evidence) 处理验证证据。

## 确定范围

以指定路径、模块或 diff 为边界，确认版本及是否包含工作区修改。读取目标测试、所调用的生产代码、测试辅助代码及判断重复所需的相关用例。范围有实质歧义时澄清，不自行扩展为全仓审计。

默认只读。用户明确要求结合 PR/module review 时，继承其基线与输出格式。

## 检查单个用例

沿“前置条件和输入 → 实际执行路径 → 断言”核对：

- **依据**：具体预期来自哪里？是否仅照抄当前实现，或用被检验的逻辑计算 expected？characterization 要保持什么兼容行为？
- **识别能力**：哪个具体错误会使测试失败？输入是否触发该错误，断言是否能区分错误结果与正确结果？
- **验证对象**：替身是否提供了本应被验证的结果？模拟数据和故障是否符合场景？交互断言是否对应契约？检查的是项目行为，还是框架机制或无契约意义的实现细节？
- **可靠性**：异步操作是否完成，异常是否吞掉，资源是否清理？独立与成组运行是否受共享状态影响？正常重构是否导致无关失败？

禁止对测试进行测试。发现以测试用例、断言或测试专用设施（fixture、mock/fake、helper、数据生成器、脚本）为被测对象的用例，应报告并建议移除；辅助代码问题通过修正或简化解决，不建议再补一层测试。

缺少依据时标为待核实，不直接判错。需要动态证据时运行相关生产行为测试；必要的故障复现或注入只在隔离副本中进行。区分测试构造失败、错误预期和生产缺陷，不改预期掩盖问题。

## 比较用例集合

区分三种重复：

| 类型 | 判断与处置 |
| --- | --- |
| 代码重复 | 操作和断言同形、仅数据不同，可参数化或共享 setup；保留必要数据行及每例失败定位 |
| 保护重复 | 保留 case 能识别同样的相关错误，且被删部分没有值得保留的定位或反馈优势，才建议删除 |
| 执行重复 | 高成本运行未提供不同边界或新证据，可缩小执行范围、调整层级或复用安全资源 |

同一规则、相同结果或覆盖同一行不能证明重复；不同输入和测试层级可能分别保护不同错误。参数化通常只减少代码，不减少执行次数。合并应列明保留的输入和断言，不把独立场景串成依赖共享状态的大 case。

检查 fixture、helper 和封装能否减少。代码减量本身有价值；比较节省的重复与增加的理解成本，不按 helper 形态或行数单独判断。

例如：

- 空字符串和纯空白名称都应被拒绝，操作与断言同形时可参数化，但保留两行数据；删除空白检查可能只使后一行失败。
- 两个用例以相同条件、入口和断言检查过期拒绝，且没有不同的定位或反馈价值时，可删去一个，指出保留用例如何识别漏掉过期校验的错误。
- 过期请求和无权限请求虽然都被拒绝，却分别保护时效与权限校验，不能因结果相同删除其中一个。

## 衡量成本并决定处置

将所防错误的触发条件、后果和增量证据，与阅读、修改、诊断、运行及不稳定成本比较：

- 重复建库、启动服务、外部调用或固定等待是否必要？
- 数据规模是否用于分页、容量或时序边界，缩小后还会触发目标错误吗？
- 更窄入口或替身能否保留所需证据，是否丢失真实事务、provider 或 Session 生命周期验证？
- 偶发失败来自产品竞态还是测试环境，重试或跳过是否只是隐藏失败？

依据代码可提出减少重复初始化、无关数据或固定等待的建议。声称运行耗时高或替代方案更快时，引用相关运行数据；缺少数据则将性能结论标为待验证，不默认新增基准测试。

据此选择保留、增强、合并、简化、替代或删除。建议合并或删除时，指出原用例保护的具体错误，以及保留用例的输入和断言如何继续识别它；行为已退役或断言无效时说明依据和必要缺口。有独有证据但成本过高时，先比较更轻方案；调整频率或取消须说明证据损失、剩余风险和允许取舍的依据，不能自行降低明确验收要求。

## 输出与执行

按共同根因合并发现。每项说明具体位置、证据与影响、最小处置，以及保留或失去的保护。优先增强已有 case，不将一处缺口扩展为假想边界清单。纯风格偏好不构成 finding。

末尾说明已审范围、实际验证和待核实事项；无可行动问题时明确结束，无须逐 case 输出检查表。

用户要求清理时实施范围内修改，对照前后场景和断言，运行受影响验证。全绿或 coverage 不变不能独自证明删除安全。
